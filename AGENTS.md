# TV Parental Control App

## Session and toolchain bootstrap

- Treat this repository as the durable project memory. At the start of Android work, read `docs/README_BUILD.md` and `.codex/skills/tv-parental-control/SKILL.md`; do not depend on prior chat context or a remembered machine-specific SDK path.
- On Windows, build from the repository root with `scripts/build.bat`. It discovers Java and reuses an extracted Gradle 9.1.0 distribution from local caches when present, otherwise the checked-in Gradle Wrapper. Do not report a missing global `gradle` command as a project blocker.
- `local.properties` and `.tools/` are intentionally machine-local and ignored by Git. Never copy their paths from another computer. Android Studio should create `local.properties`; install SDK Platform 37 and use Android Studio JBR/JDK 17+ or set `JAVA_HOME` for the current shell.
- Install to the emulator with `scripts/install_emulator.bat`; install to the TCL TV with `scripts/install_device.bat`. The TV installer discovers ADB from SDK environment variables, `local.properties`, or PATH and uses TCL MultiScreen Interaction.
- The optional local Gradle cache is not required on a fresh clone. The committed Wrapper pins Gradle 9.1.0 and may download it on first use.

## Product context

- Target device: Thunderbird (LeiNiao) Android TV, Android 9/API 28.
- ADB endpoint: `10.0.0.8:5555` (updated on 2026-11-12 after the TV's IP changed).
- The app presents multiple-choice questions in a large centered floating window (about 86% x 82% of the screen, dimmed background) above the current TV app. D-pad moves the selection and OK submits it.
- Fresh installs automatically initialize the 6-key parent PIN to `UDLRUU` (Up, Down, Left, Right, Up, Up), matching the backend PIN reset. Parents can change it on the launcher; existing PINs are preserved, and only a salted SHA-256 hash is stored. On the wrong-answer lock screen the password ends the lockout early; 5 wrong attempts trigger a 30-second cooldown. On the daily-quota lock, the parent PIN lifts only the daily limit until standby, shutdown or the next Android boot; subsequent viewing is recorded separately as parent-unlocked time without increasing the quota counter or spending rewards. Usage windows and question locks remain enforced.
- Parents manage the question bank and usage rules through a Web admin page, initially hosted on a local computer and later deployable to Alibaba Cloud ECS.

## Development rules

- Keep Android app interface text in English except the account-binding entry and dialog, which are Chinese at the user's request. Keep the backend admin interface and its user-facing messages in Chinese unless the user explicitly requests another language.
- Use Kotlin and Android Studio for the Android app. Keep Android dependencies minimal and support API 28.
- Keep the launcher and overlay usable with a TV remote: large labels, visible focus, D-pad navigation, and OK activation.
- Global display requires `SYSTEM_ALERT_WINDOW`; grant it through the documented ADB installation workflow, never silently from the app. The launcher shows permission status without permission buttons or automatic settings redirects.
- Keep package name `com.example.tvparental` unless the user explicitly changes it.
- Unlock challenges ask five questions; at least four correct answers unlock access. A score below four starts the configured lockout and restarts the challenge when it ends; the parent PIN remains an override.
- The daily-use counter estimates screen-on time, persists locally, resets by local calendar day, and must not count time during an answer lockout.
- Use a foreground service for usage tracking. Re-arm question alarms after `LOCKED_BOOT_COMPLETED` and `BOOT_COMPLETED`; keep alarm bookkeeping available during direct boot.
- Randomly select from the 50 built-in questions, avoid repeating the previous question, and preserve an unanswered question across service restarts.
- Each challenge question is submitted once. After all five questions, a score below four starts the configured lockout; a daily quota exhaustion blocks until the next local day.
- The default rules are 60 minutes per day, one question every 10 minutes, a 10-minute wrong-answer lock, and a 5-minute sync interval (configurable 1-60). The remote backend can change these values.
- Daily usage rules support per-weekday allowed time windows and disabled time windows. Disabled windows always take priority when they overlap allowed windows.
- The device polls the backend: full sync on service start, then every `syncIntervalMinutes` from the synced settings.
- The device syncs questions and rules from `https://tvparental.mediainsight360.com/api/v1/device/state` after account binding. The TV displays a server-generated six-digit code valid for five minutes; the logged-in parent enters it in Web admin and confirms the device. Device requests require the saved random credential, device ID and current binding ID. Never put account passwords in Android.
- Backend code uses Python's standard library. Keep runtime state and secrets outside version control. Use HTTPS for any public ECS deployment.
- Check whether the TV is reachable before a device test. This TCL firmware rejects `adb install -r`; use TCL MultiScreen Interaction and confirm the install on the TV. Follow `docs/INSTALL_TCL.md`.

## Current implementation

- Android sources are under `app/`; the 50-question seed bank is `app/src/main/assets/questions.json`.
- The launcher displays today's use and provides actions for the parent PIN, manual sync, advanced settings, Chinese account binding, and pausing or resuming the timer. The binding dialog automatically gets/renews its code and polls binding status; it has only a Close button. The backend URL is fixed in `ControlState.BACKEND_URL`.
- Startup challenges trigger only on the first startup of each TV-local calendar day. The boot receiver and launcher share a synchronously persisted date claim; missing overlay permission does not consume the claim. Later reboots or launcher openings that day do not trigger another startup challenge; interval questions and lock recovery keep their normal behavior.
- Daily usage normally checkpoints synchronously every 10 seconds while the service is scheduled, plus final samples on screen-off, shutdown, and service destruction. Samples settle the previous screen/overlay state before transitions. A 32-date usage ledger preserves totals, extensions and reset IDs across clock jumps; an unseen older boot date cannot clear the active day. Lowering a quota never lowers already-used time. See `docs/USAGE_ACCOUNTING.md` for limits and validation.
- Manual timer pause and resume require the parent PIN. The pause survives app recovery in the same Android boot, expires on screen-off standby or shutdown, and is ignored on the next boot. While paused, regular and reward debits stop and automatic questions are hidden without discarding an unfinished challenge. Automatic questions are rearmed on resume; quotas, allowed hours and active locks remain enforced.
- Report cumulative daily usage immediately on usage-service startup and every screen-on, bypassing the normal minute interval. Failed reports retry after 5 seconds; network availability triggers an immediate retry. Requests are serialized, and an immediate request arriving during a report queues one follow-up. The minute interval starts after a successful report.
- PIN-protected Advanced settings uses full-row focusable toggle cards with ON/OFF indicators, a scrollable list and fixed Done action. Up/Down moves focus, OK toggles and Back closes. The app has no accessibility authorization button; shortcut blocking is authorized in system settings. The local `Block Recent Watch button` switch is on by default and preserves an explicit off choice. `RecentWatchGuardService` requires accessibility access, consumes TCL scan code 613 when delivered, and closes only the confirmed TCL Recent Watch plugin activity as a firmware fallback. See `docs/REMOTE_BUTTON_CONTROL.md`; preserve Aerial and other accessibility services when testing.
- The same accessibility service provides an independent `Block Live TV button` switch, on by default. It consumes the observed Live TV key (`KEYCODE_TV`, scan code 377). Do not close all `com.tcl.tv.TVActivity` windows as a fallback: that activity also handles TV input sources. Key filtering remains requested while either shortcut switch is enabled.
- The challenge unlocks after 4 correct answers out of 5. Every submitted answer is queued locally and reported to the backend; daily cumulative screen-on usage is reported once per minute.
- Wrong answers mark the selected option red and gently pulse the correct option in green with the correct answer shown for 5 seconds before advancing or showing the final result. Question changes reuse the attached overlay window to avoid flashing the entire panel or dimmed background. Remote input cannot change the feedback or submit again. Test questions use the same wrong-answer feedback before closing.
- Wrong-answer locks display one complete work: prefer a poem from this challenge's incorrectly answered poetry questions, otherwise choose a random poem from the bank, with bundled works as an offline fallback. The selected work persists with the lock and never scrolls. Short works retain the original typography; overflowing works put a smaller author after the title and automatically shrink body text and line spacing to fit. The countdown and PIN stay reachable. Questions optionally carry `poem: {title, author, content}` through generation, storage, sync, and snapshots. Backend snapshots asynchronously supplement missing poetry text through DeepSeek and cache it; the TV never calls the model.
- Daily-quota locks also display a complete random poem from the bank, with bundled works as a fallback. The work stays unchanged during that overlay session, including PIN entry and reward challenges. The footer retains reward use and hard-question challenges when eligible, always offers `Unlock with PIN`, and has no `Not now` button.
- The question table's action column has a persistent `priority` checkbox. New five-question challenges shuffle priority questions first and fill remaining slots with regular questions, retaining previous-question avoidance and cached/active challenge recovery. Test questions use the same priority selection. Sync and saved question snapshots preserve the flag; existing questions default to false.
- The question overlay has a small bottom `SKIP` button, reachable by pressing Down from either bottom answer. It requires the existing parent PIN, shares the 5-attempt/30-second cooldown, and ends the current challenge without recording an answer; Back returns to the same unanswered question. PIN skipping schedules the next normal question interval and does not grant extra viewing time or bypass allowed hours. Test-question skipping leaves the real challenge and its deadline untouched.
- The admin `/records` page displays daily usage and answer history. Backend state persists these records in its ignored runtime data file.
- Typed viewing intervals (`regular`, `reward`, `parent_unlocked`) and actual screen-on question/feedback time (`answering`) are checkpointed in the same 32-date usage ledger and included in each current-day report as a full `usageIntervals` snapshot. Daily-limit PIN overrides and PIN-protected timer pauses record parent viewing separately; neither that time nor answering debits regular quota or rewards. Standby, passive locks and PIN entry are excluded. Backend records show the total of all four categories, with second-precision time ranges and type labels. Retries replace snapshots without duplication; counts for any category cannot regress, including when the regular counter stays fixed. Quota resets clear only regular intervals, preserving answer, parent and reward details. Continuous groups exclude pauses from their counted milliseconds. Historical totals without enough interval data display an explicit unlocated duration; do not invent viewing times or lower the cumulative total to match partial details.
- Each five-question record stores its popup trigger separately from its result: first startup of the day, configured interval, wrong-answer lock expiry, or reboot recovery. Reboot recovery links to the interrupted session and reuses its cached questions; a boot-count guard prevents a late boot broadcast from ending the recovered session again. Shutdown records the interruption when delivered; abrupt power loss is detected on the next boot. Parent PIN skipping has its own result. Older records without a trigger display as unknown.
- The admin `/poems` page lists and searches works previously added to the question bank. SQLite keeps this history after questions are deleted or removed by correct answers, backfills from existing questions and answer snapshots, and groups by title and author. AI poetry generation shows matching history as a reminder; previews alone are not recorded.
- Parents can grant a selected TV reward minutes in `/settings`, where its remaining reward balance appears after the grant button and updates on device selection or a successful grant. The same page sets a per-device daily reward cap (default 30 minutes). The balance carries across days. After regular time runs out, the TV offers reward use when viewing is otherwise allowed. Confirmed reward time is charged only while watching. Regular usage resets leave the reward balance and that day's reward consumption intact.
- Next to PIN reset, the admin can reset a selected device's usage for today. A per-device/date command clears the TV's used time and temporary extension once on sync, preserving usage windows and challenge locks. Usage reports carry the applied command ID so in-flight totals from before a reset cannot restore the old count. Other dates, devices, PINs and answer history are preserved.
- Usage reports include `utcOffsetMinutes`; the backend derives the reset date from its current clock in that device's reported time zone. The browser sends only the device ID and displays the server's resulting date. If the device has not reported its time zone, require an app upgrade/sync rather than guess a date.
- The Web admin supports registration at `/register`; each account owns independent questions, poems, rules, devices and records. One account can bind multiple TVs sharing its rules and bank. Existing admin credentials/data remain account 1. The main SQLite database stores accounts and device bindings; additional account state lives beside it in `<database-name>.accounts/<id>.sqlite3`. Back up the main database and this entire directory together. `--set-admin` can reset an existing username's password. New databases still initialize the original account as `admin/admin`.
- Web navigation groups usage (`/settings`, `/records`), content (`/questions`, `/poems`), and device maintenance (`/devices`, including binding/unbinding, PIN and usage resets). Unbinding revokes credentials immediately; historical records remain with the original owner. On binding changes Android clears previous account caches and reporting queues while preserving device PIN/switches. The first binding to account 1 retains legacy local records. Reinstalling an unbound device replaces its pending credentials and invalidates its previous code; an already-bound device still requires its original owner to unbind, reported as HTTP 409 with `errorCode: device_already_bound`. Android must not interpret a generic 401 as an ownership conflict. Emulator installs use `adb install -r` to retain local data. Anonymous device endpoints are closed; deployment probes use `/api/v1/health`.
- The question bank supports DeepSeek question generation: poetry questions use a poem title, while math, geography/history, and science questions are generated randomly by category. Preview and selected batch import are supported. `DEEPSEEK_API_KEY` stays in the server environment; the standard-library client in `backend/deepseek.py` uses `deepseek-flash` and JSON output. Generation never writes the bank; batch import validates every item and skips duplicate prompts.
- The Web backend and admin page are under `backend/`; run its API tests with `python -m unittest discover -s backend/tests -v`.
- ECS deployment uses host-level Caddy + a `tvparental` systemd service running as dedicated user `tvparental-deploy`, code at `/var/www/html/tvparental`. `backend/compose.yaml` remains as a Docker alternative. Keep `backend/.env` and `backend/data/` private.
- `.github/workflows/deploy-ecs.yml` auto-deploys backend changes on `main` via rsync + SSH + `systemctl restart tvparental`; required secrets are documented in `docs/DEPLOY_ECS.md`.
- Windows local Android builds use `scripts/build.bat`; Gradle Wrapper is pinned to 9.1.0. The SDK path in `local.properties` is per-machine and must not be committed.
- TCL MultiScreen Interaction installation and the floating overlay over the launcher were verified previously. Grant overlay access with ADB `appops`; the launcher does not open a permission page and the app never grants it silently. Video-app overlay behavior and reboot recovery should be rechecked after significant Android changes.
